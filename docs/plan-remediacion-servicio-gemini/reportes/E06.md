## Diagnóstico y decisiones técnicas
1. **Credencial de Puesto / Hardware Terminal (S09):**
   - Se introdujo el endpoint `POST /staff/terminal/provision` para enrolar y autenticar tablets de salón o cocina con rol `TERMINAL` y flag `isTerminalOnly: true` (validez de 7 días).
   - En `auth.middleware.ts`, un token de puesto con `isTerminalOnly: true` tiene acceso **exclusivamente a lecturas (GET)**. Cualquier intento de mutación (POST, PUT, PATCH, DELETE) es interceptado y denegado con HTTP 403 `FORBIDDEN`, código `OPERATOR_PIN_REQUIRED` y mensaje amigable solicitando el PIN del operador.
2. **Sanitización de Datos en Pantalla Desatendida (S09):**
   - En `ServiceWorkspaceService.getSnapshot`, cuando la consulta es realizada por un puesto desatendido (`isTerminalOnly: true`), la respuesta preserva el listado de llamados y tareas pendientes (ej. "Mesa 10: Solicita cuenta"), pero anonimiza saldos (`balanceMinor: undefined`, `summary: 'Solicita cuenta'` en lugar de exponer importes exactos) y omite la lista detallada de `accounts` (`[]`), protegiendo la privacidad financiera del local ante clientes que miren la tablet en la barra o mostrador.
3. **Restricción de Ámbito para Tokens Temporales (S13):**
   - En `auth.middleware.ts:verifyManagerRole`, se bloquean estrictamente tokens temporales (`temp: true`) con HTTP 403 `TEMPORARY_TOKEN_NOT_ALLOWED`, impidiendo que un token temporal de cobro o reautorización pueda crear o listar personal, modificar cartas o alterar configuraciones de administración.
   - Si un token temporal tiene un alcance acotado de mesa (`tableId`), cualquier intento de invocar endpoints con un `tableId` diferente es denegado con HTTP 403 `TOKEN_SCOPE_MISMATCH`.
4. **Atribución Inmutable de Peticiones y Concurrencia (S07):**
   - Cada petición mutadora (`claimTask`, `resolveTask`, etc.) viaja con el Bearer JWT firmado del mozo actuante. El servidor extrae `request.staffUser.sub` y lo asienta de manera transaccional e irrevocable en la base de datos (`serviceTaskClaim.staffUserId`).
   - Si otro mozo ingresa su PIN en la tablet compartida mientras la petición anterior está en vuelo, la autoría en DB permanece intacta en el mozo original sin herencia ni mezcla de privilegios.
5. **Revocación en Tiempo Real por Estado en DB:**
   - Si un mozo es dado de baja en la base de datos (`prisma.staffUser.delete`) o cambia de rol/restaurante, su token firmado es invalidado en el siguiente request con HTTP 401 `UNAUTHORIZED`.
