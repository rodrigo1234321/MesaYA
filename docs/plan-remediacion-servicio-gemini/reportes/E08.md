## Diagnóstico y decisiones técnicas
1. **Un Solo Dueño del Polling HTTP (H07 / D03):**
   - Anteriormente, `App.tsx` ejecutaba `useSSE` consultando `/calls` cada 3 segundos, mientras `ServiceWorkspace` ejecutaba su propio `scheduler` consultando `/service-workspace` cada 5 segundos. Cuando ambas vistas estaban activas, se generaban requests duplicados y desfasados; y cuando el usuario cambiaba a "Fila puerta" o "Rewards", se perdía la visibilidad de entregas de cocina y cuentas por cobrar.
   - Con `useServiceSync.ts`, el shell `App.tsx` mantiene un único `PollingCoordinator<ServiceWorkspaceDTO>` que consulta periódicamente el endpoint consolidado de Servicio.
   - `ServiceWorkspace` recibe `syncSnapshot`, `syncLoading`, `syncError` y `onRefresh` como props, omitiendo su propio scheduler interno cuando el shell le suministra los datos.
2. **Indicador de Conexión Real y Tiempo Transcurrido (H07 / S11):**
   - Se erradicó por completo cualquier asignación que pusiera verde el indicador en función de la pestaña activa (`activeTab === 'service'`).
   - El indicador visualiza ahora 5 estados reales:
     - `connected`: verde con texto "Terminal sincronizado · hace X s".
     - `stale`: ámbar si transcurren más de 12 segundos sin respuesta exitosa en foreground ("Sincronización demorada · hace X s").
     - `disconnected`: ámbar pulsante ("Sin conexión · reintentando (hace X s)").
     - `auth_error`: rojo si la sesión o PIN expiró ("Autorización de puesto vencida (reingrese PIN)").
     - `connecting`: ámbar durante el arranque inicial.
3. **Avisos Permanentes y Deduplicados Fuera de Atención (S10):**
   - Mientras el usuario se encuentra navegando pestañas secundarias (`activeTab !== 'service'`), si surgen llamados activos o tareas urgentes (platos listos para entregar o cuentas por cobrar), la aplicación despliega un banner persistente destacado con botón:
     `Hay X llamados activos en salón · [Abrir Atención →]`.
   - La alerta sonora (`playChimeAlert`) se dispara una sola vez ante la llegada de nuevos eventos no conocidos previamente (mediante `knownTasksRef`), evitando campanadas repetitivas en cada tick del polling.
4. **Activación y Prueba de Audio por el Usuario:**
   - Para cumplir con las políticas de autoplay de navegadores modernos (Web Audio API suspendida sin interacción del usuario), se integró el botón "Probar sonido" en la cabecera, permitiendo desbloquear y comprobar el timbre con un solo toque.
5. **Reconciliación Inmediata y Descarte Fuera de Orden (S11):**
   - Al volver de una pestaña oculta (`document.visibilityState === 'visible'`) o recuperar la red (`window.ononline`), el coordinador dispara inmediatamente `triggerNow()`.
   - Si una respuesta previa llega demorada después de haberse iniciado un nuevo ciclo, el número de secuencia interna del coordinador (`_requestSeq`) descarta la respuesta desfasada sin sobrescribir el estado fresco.
