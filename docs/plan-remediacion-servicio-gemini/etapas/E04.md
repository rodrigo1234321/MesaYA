# E04 — Rotación de huella de PIN y legado

Estado inicial: NOT_STARTED. Dependencias: E03.

## Resultado

Mantener acceso y unicidad durante cambios controlados de clave.

## Archivos y responsabilidad

staff.service.ts, environment.ts, configuración de ejemplo sin secretos, tests staff-pin-uniqueness. Este alcance corresponde al ejecutor de esta ficha. Leer instrucciones aplicables; preservar cambios ajenos. Si se habilitan agentes en otra ejecución, asignar archivos explícitos y no revertir ediciones de otros.

## Trabajo acotado

Separar concepto de huella de cifrado general. Elegir y documentar rotación versionada con clave actual/anterior y transición validada, o mecanismo equivalente probado. Revisar necesidad de scan bcrypt acotado: no recomendar escanear todos los usuarios ilimitadamente. Dos procesos con claves distintas no deben crear el mismo PIN dos veces; coordinar rollover y/o impedir escrituras ambiguas durante transición.

## Verificación obligatoria

S24 con legado null, claves antigua/nueva, secreto ausente, duplicados y varias instancias. Probar rollback de configuración, sin imprimir PIN/huellas.

## Criterio de cierre

Login correcto, recuperación documentada y unicidad entre versiones. No sólo quitar fallback ni documentar «no rotar nunca»; límites antiabuso permanecen.
